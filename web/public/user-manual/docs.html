Data & feature engineering

Underlying OHLCV lives in underlying_bars; options in options_contracts / options_bars. Ingestion: data/sync.py (Massive) or data/etrade_sync.py (E*TRADE). Backtests and forecasting read the same tables.

  • features.loader.load_underlying_series(symbol, from_date, to_date) — OHLCV DataFrame (same path as backtests).
  • features.ohlcv_features.build_ohlcv_features(df, …) — returns, return_lag_*, sma_*, rolling volatility (annualized), target (next-period return). Parameters: target_col, return_lags, sma_windows, vol_window, drop_na.
  • features.ohlcv_features.get_feature_columns(…) — column list for a config.
  • features.macro_features.load_macro_features(from_date, to_date, series_ids=None) — wide macro DataFrame from DB (e.g. fred_GDP).
  • features.macro_features.join_macro_features(ohlcv_df, macro_df, fill_method="ffill", prefix="macro_") — forward-fill and join.

Forecast API: include_macro: true joins macro features; response includes macro_enriched: true when enrichment succeeds. Options IV in options_bars.implied_volatility feeds strategy and Research Assistant context.

Authentication

JWT bearer tokens. Web UI stores the token in localStorage (ol_token) and sends Authorization: Bearer … on requests. Tokens expire after 24 hours. No refresh token — log in again.

EndpointPurpose
POST /auth/registerJSON body: email + password (≥ 8 chars). 409 if email exists.
POST /auth/loginReturns access_token. 401 if invalid.
GET /auth/meCurrent user (requires token).

Protected route prefixes (examples): /user/settings, /lab/backtests, /lab/strategy-engine, /lab/etrade, /forecasting, /research, /economic, /volatility, /risk, sync, contracts delete. Public examples: GET /, GET /symbols, GET /bars (read-only market data per deployment).

CLI example (local API):

TOKEN=$(curl -s -X POST http://localhost:8000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"yourpassword"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")
curl http://localhost:8000/user/settings -H "Authorization: Bearer $TOKEN"
Production Set JWT_SECRET_KEY (generate with python -c "import secrets; print(secrets.token_hex(32))"). Set ALLOWED_ORIGINS to your real web origin(s). Broker/data keys in Settings are stored in the database — use HTTPS and protect DB access.

Time-series forecasting

Package: forecasting/. Models: ARIMA (ARIMAForecaster, default order often (1,0,0)) and GB (GBForecaster, HistGradientBoostingRegressor, lagged features, n_lag default 5).

Interface: fit(series), predict(horizon), predict_direction(horizon). ARIMA optional: get_confidence_interval.

Registry: GET /forecast/runs lists saved runs (TRADING_FORECAST_REGISTRY).

Evaluation: evaluate_forecast → directional accuracy, RMSE, MAE; backtest_returns_from_signals for simple long/short signal returns.

Dependencies: statsmodels, pandas, numpy, scikit-learn.

Strategy engine

Strategy kinds: vertical_spread_call, vertical_spread_put, straddle, iron_condor, calendar_spread_call, calendar_spread_put. European payoff at expiry; per-share.

POST /strategy-engine/evaluate — forecast mean/std or distribution, strikes, optional premium_paid, optional include_backtest=true for historical comparison.

POST /strategy-engine/discover — auto forecast + rank all strategies by expected value (spread_width_pct default ~2%).

Code: strategy_engine/payoff.py, strategies.py, expected_value.py, breakeven.py.

Research Assistant (LLM)

OpenAI gpt-4o-mini when OPENAI_API_KEY is set (env or user Settings). Otherwise structured placeholder.

RAG: research_assistant/rag.py — TF-IDF cosine retrieval; optional chromadb for semantic search. POST /research/rag/ingest, POST /research/rag/retrieve.

Routes: POST /research/explain, POST /research/analyze (full pipeline).

UI: /dashboard/research — Run forecast, Evaluate strategy, Full analysis, Position sizing, Recent forecast runs (see docs/RESEARCH_ASSISTANT.md for layout).

Risk tools

Kelly: f* = (p×b − q)/b; half-Kelly recommended. POST /risk/position-size, POST /risk/breakeven. Strategy evaluate includes break-evens with premium_paid.

Metrics: max_drawdown, volatility_annualized, var_historical (95%). Code: risk/position_sizing.py, risk/metrics.py.

Volatility dashboard

GET /volatility/{symbol}?from_date=&to_date= — HV 10/20/30/60, IV, IV Rank, IV Percentile, expected move 30d, iv_series, hv_20_series. UI: /dashboard/volatility; chart component VolatilityChart.tsx.

IV Rank / IV Percentile definitions and strategy guidance thresholds match docs/VOLATILITY.md.

Macro & economic data

GET /economic/series — query: source = fred | bls | bea, series_id, optional start_date / end_date. Response: normalized points: [{date, value}].

Keys: FRED_API_KEY, BLS_API_KEY, BEA_API_KEY (env or Settings; user settings win when set).

Dashboard: /dashboard/economic — load series, charts, “Import all presets”. Bulk CLI:

PYTHONPATH=. python3 scripts/sync_economic.py --all-presets --from 2015-01-01 --to 2024-12-31 --to-db

Uses TRADING_API_URL (default http://localhost:8000) to call the API.

TSF Options AI — architecture

From docs/TSF_OPTIONS_AI_IMPLEMENTATION_PLAN.md. Phases (data, forecasting, strategy engine, LLM, RAG, E2E, discovery) are implemented.

Data flow (conceptual): Massive/E*TRADE → storage → features → forecasting → strategy_engine → research_assistant (RAG + LLM).

Market Data → storage/ (ORM) ─┬→ Backtrader backtests
                              └→ features/ → forecasting/ → strategy_engine/ → research_assistant/

Principles: shared data layer for backtest vs forecast; modular pipeline; placeholder LLM without key; per-user secrets in DB with env fallback; same CDK stacks across dev/staging/production with infrastructure/config.py.

Tools: Python ≥ 3.12, Node ≥ 18, AWS CLI, CDK ≥ 2.170, Docker running for cdk deploy.

Deploy (from repo root): npm run deploy:dev / deploy:staging / deploy:production, or cd infrastructure && cdk deploy --all --context stage=… --context account=… --context region=….

CI/CD: test.yml on push/PR; deploy-staging.yml on main; deploy-production.yml on tag v*.*.*. Configure GitHub Environments and AWS secrets per DEPLOYMENT.md.

Health: GET /health returns status and DB check.

Local Next env: copy web/.env.local.example → .env.local, set NEXT_PUBLIC_API_URL=http://localhost:8000.

Troubleshooting: Lambda 502 → CloudWatch logs, SG/RDS connectivity, cold start timeout; Amplify build → ensure NEXT_PUBLIC_API_URL is defined.
